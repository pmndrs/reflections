# Handoff board

The working state of the project: who is on what, which interfaces the workstreams agreed on, and where each one stopped. `docs/SPEC.md` is the plan; this is the log of executing it. Update your row when you stop, even mid-task.

## How we work (agents read this first)

- **Build features first.** Get a pass working end to end on a real GPU (`pnpm check`), commit, move on. Don't sink time into squeezing milliseconds or making a test match an expectation. If a number is off, write it down (row below, or `DIVERGES.md` if it's a divergence) and keep going. Measurement is for the **gates** in SPEC's roadmap and for big decisions, not for every step.
- **Time-box.** If something fights you for more than ~30 minutes of attempts, record what you tried in your row's "stuck on" and move to the next part of your scope.
- **Diverging from a source is fine. Hiding it isn't.** Every knowing difference from FFX, idTech, three, Lagarde, etc. goes in `docs/DIVERGES.md`.
- **Commit after every run** (CLAUDE.md rule 4): what was tried, numbers, verdict, failures included. Explicit paths, never `git add -A`.
- **Stay in your lane.** Each stream owns the paths in its row. Touching a shared file (`packages/*/src/index.ts`, `src/*.ts`, `package.json`, `scripts/run-headless.mjs`) is allowed but keep the edit to adding your exports or your check, so merges stay trivial.
- **Stopping a server:** kill by port (`lsof -ti tcp:<your port> | xargs kill`), never `pkill -f vite`. A pattern kill takes down every other worktree's server too.
- **Ports.** Each worktree runs its examples server on its own port: `REFLECTIONS_PORT=<port> pnpm examples` / `REFLECTIONS_PORT=<port> pnpm check`. 5370 is the maintainer's own server: agents and the lead never use it (the lead runs main-checkout checks on 5389). `pnpm check` reuses any server already on its port, so a wrong port means testing someone else's build. 5310 belongs to another project.

### Radiance fallback (SSSR miss → probes/env), used by W3 now, filled by phase 2

A WGSL snippet plus a bind group, like the trace seam:

```wgsl
fn sampleRadianceFallback(P: vec3f, dir: vec3f, roughness: f32) -> vec3f
```

W3 ships a default implementation (a single `texture_cube<f32>` environment, or a constant colour) and takes any other snippet + bind group layout at pipeline creation. As built (W3): `P` and `dir` are world space; `roughness` is **perceptual** (0 for screen-space misses, which are lerped by hit confidence as in FFX; `sqrt(alpha)` for reflective pixels above the roughness threshold). The snippet's bindings live in `@group(1)`; pass its layout as `radianceFallback.layout` and the bind group as `inputs.fallbackBindGroup`. It may read the tracer's uniform block `P` (`P.iblFactor`, `P.fallbackColor`).

Filled by W7 (phase 2): `probeRadianceFallback(set: ProbeSet)` returns `{ wgsl, layout, bindGroup }`. Its `sampleRadianceFallback` is `probeRadianceWithEnvironment(P, dir, roughness) * P.iblFactor` over the set's lookup module at `@group(1)` (atlas, sampler, table: 1 storage buffer). The same object plugs into `createScreenSpaceReflections({ radianceFallback })` + `inputs.fallbackBindGroup` and `createTracedReflections({ radianceFallback })` + `fallbackBindGroup` (traced misses, and `fallbackHitShading`'s probes at the hit along N at roughness 1).

### Trace seam (W8 → @pmndrs/bvh, W7)

```ts
// packages/core/src/trace/provider.ts (exported from @pmndrs/reflections/core)
interface BindingSlot { group: number; firstBinding: number }          // = ddgi's BindingSlot
interface TraceProvider {
  name: string;
  code(slot: BindingSlot): string;   // bindings at slot, in `entries` order; defines traceFirstHit (+ traceHitMaterial if capabilities.hitMaterial)
  entries: readonly ModuleBindingEntry[]; resources(): readonly GPUBindingResource[]; version: number; storageBufferCount: number;
  capabilities: { hitNormal: boolean; hitMaterial: boolean };
  layoutVersion?: number;            // @pmndrs/bvh: GPU_LAYOUT_VERSION, checked by the provider at start-up
}
```

```wgsl
// declared by the pass (HIT_WGSL) before the provider's code
struct Hit { t: f32 /* < 0: miss */, triangle: u32, barycentrics: vec2f /* weights of corners 1, 2 */, material: u32, instance: u32, normal: vec3f /* world, 0 if !hitNormal */, frontFace: bool }
struct HitMaterial { albedo: vec3f, emissive: vec3f }
fn traceFirstHit(origin: vec3f, dir: vec3f, tMax: f32) -> Hit                 // provider
fn traceHitMaterial(hit: Hit) -> HitMaterial                                  // provider, or the pass's grey default
fn shadeTracedHit(hit: Hit, P: vec3f, N: vec3f, dir: vec3f) -> vec3f          // HitShading (pass option); may call sampleRadianceFallback
```

The traced pass binds group 0 (itself: 3 storage buffers, 4 storage textures), 1 (radiance fallback, same snippet as SSSR), 2 (provider), 3 (hit shading). With 3 storage buffers of its own, a provider may use 5 on a default device, 4 with the probe fallback (its table is one more). F2: `createTracedReflections` counts all four groups (storage buffers and storage textures; `RadianceFallback` / `HitShading` declare theirs with `storageBufferCount` / `storageTextureCount`) against `device.limits` and throws with the limit to raise.

**For @pmndrs/bvh to plug in:** a ~40-line wrapper whose `code(slot)` is `traceModuleWgsl(slot)` (+ its dependencies) followed by `traceFirstHit` calling `giTraceClosest(GiRay(origin, 0.0, dir, tMax))` and mapping `GiHit` (t, triangle, barycentrics, frontFace map one to one). What it lacks today: (1) a hit normal (GiHit has none; the walk has the triangle's corners and the instance transform, so a `giHitNormal(hit)` helper or a `normal` field would do; without it `hitNormal: false` and the pass shades with -dir); (2) an instance → material table (an extra binding, or a user word in the instance record); (3) the exported `GPU_LAYOUT_VERSION` constant (the split doc plans it; not in the source yet). Its 3 storage buffers fit (6 of 8 with the pass).
