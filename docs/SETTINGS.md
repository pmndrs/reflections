# Settings guide

Every tuning knob the package and the examples expose, with its default, what it trades and, where one was measured, its GPU cost. The same list drives the tuning bench, `examples/showcase/bench.html`: each row is a control there and a URL key (`bench.html?<key>=<value>`, booleans as 1 / 0), so a link reproduces a view.

- **Default:** the package's default (what you get without passing the option). "examples:" is what the showcase and the bench use where that differs.
- **Apply:** *live* changes without a reload; *rebuild* is taken at construction (on the bench: the Rebuild button).
- **Cost:** measured GPU time with its source (docs/HANDOFF.md, docs/DIVERGES.md). Blank: not measured on its own. Small costs add up; a later "fast" preset will need them.
- **Applies to:** the bench's methods (ours raw / denoised / + RT, probes only, three SSR raw / + denoise / + FFX, path traced).

## Presets

Named bundles of the settings below, in core (`REFLECTION_PRESETS`, `reflectionsPreset(name, overrides)`): an adapter applies the tracer part to its pass and the denoiser part to its hybrid resolve, and settings you pass explicitly win key by key. three: `new ScreenSpaceReflectionsPass(renderer, { preset, settings })` and `new HybridReflections(ssr, { preset, denoiser })` at construction, `applyReflectionsPreset({ ssr, hybrid }, name, overrides)` at runtime (rebuild your composites when it returns `resolutionChanged`). Bench: `preset` (the first control). Measurements: docs/research/w77/.

## What changes when ray tracing is on

Turning the ray-traced fallback on (`ScreenSpaceReflectionsPass({ trace })`, `setTraceProvider()`, `rayTracing`; in core, `missesTraced: true` on the tracer's dispatch) changes these defaults. **An explicit value always wins**: set the field to keep the RT-off value. The bench shows the effective value of an unset field.

| Setting | URL key | Default | With RT | Why |
|---|---|---|---|---|
| Thickness per view depth | `s.thicknessDepthFactor` | 0 | 0.02 | W76 (maintainer's call on X1 #2, D5001): the relative test at 0.02 x view depth stops thin geometry turning into a slab (lineSpreadThin x4.25 -> x1.45..x2.2 of the PT's width) and is flat on carConcept, toyCar, chess, Sponza with RT (within 0.15 MAD); the rays it rejects go to the RT pass. Without RT they would take the probe (Sponza +1 %, more misses), so the default stays 0 there. `thicknessDepthFactor: 0` (or mode 'add') restores the old test. |
| Thickness depth mode | `s.thicknessDepthMode` | `add` | `relative` | W76: with Thickness per view depth, the RT default (relative 0.02), only while both are unset. An explicit 'add' keeps the pre-W76 thickness with RT on (the factor then defaults to 0); an explicit factor alone keeps 'add' too. |

Behaviour of the RT path that differs from RT off (no setting to miss, listed for completeness):

| What | Why |
|---|---|
| The tracer runs with `missesTraced: true` | The three adapter sets it while its traced pass runs; it is what switches the RT defaults above on in core (`resolveScreenSpaceSettings`). A direct core user sets it on the tracer's dispatch. |
| On-screen traced hits are re-shaded without a visibility ray | D3542: as the screen-space re-shade (no BVH there); with the ray a mirror seen in a mirror went black in stripes. `traceSettings.hitShadeVisibility: 'all'` adds it (D3640). Off-screen traced hits keep D3513's ray. |
| Specular occlusion skips traced misses | W45 (D3551, D4513): a traced miss left the scene unblocked, so Lagarde's AO guess would occlude it twice. Untraced pixels keep it (`specOcc`). |
| Lobe filter where hits mix (`s.hitLobeFilterMixed` < 1) acts | D3641: it reads last frame's hit source, which only the traced pass writes; without RT it changes nothing. |
| `rayReuse: 'ratio'` leaves traced pixels alone | D5043: the resolve runs before the traced pass, which overwrites the miss list's pixels; screen and traced hits never mix in it. |
| The traced lobe filter follows the tracer's lobe split | D5021 / W76: with the cone + compensation defaults a traced hit's specular is filtered by hitLobeFilter x alpha x sqrt(mirrorBias) (the share the narrowed sample leaves out); `traceSettings` can override it. |

## Not exposed

| Option | Why |
|---|---|
| `settings.fallbackColor` | The three adapter forces the tracer's constant fallback black (the composite adds the probe); a constant colour is meaningless there. |
| `traceSettings.fallbackColor, hitColor, hitShading` | The adapter passes black and the tracer's own `hitColor` / `hitShading` (Hit colour / Hit specular above). |
| `trace option `lights`` | Constructor-only (`ScreenSpaceReflectionsPass({ trace: { provider, lights } })`); the examples attach the provider later with `setTraceProvider`, so the default (on) stays. |
| `ReflectionProbes.refitClamp, frameIrradiance` | Only with a frame-irradiance re-fit, which the showcase scenes don't run. |
| `@pmndrs/upscaler debugView` | A debug overlay, not a tuning knob. |
