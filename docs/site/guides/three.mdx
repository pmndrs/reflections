The three.js adapter is the main one. It has every feature in the library: probes, screen-space reflections, the
ray-traced fallback, the denoiser seam, presets and the hybrid resolve. `Reflections.create` sets them all up in one
call. See the [adapter comparison](/guides/adapters) for the other engines.

It needs `WebGPURenderer` from `three/webgpu` (r187 or newer) and works with `MeshStandardMaterial` and
`MeshPhysicalMaterial`, and their node versions.

## Install

```bash
npm install @pmndrs/reflections three
```

| Package | Range | When |
| --- | --- | --- |
| `three` | `>=0.187.0` | Always. |
| `@pmndrs/raytracer` | `^0.1.0` (optional) | `rayTracing: true`, the ray-traced fallback. |
| `@pmndrs/bvh` | `^0.1.0` (optional) | Install with `@pmndrs/raytracer`. |
| `denoiser` | `^2.0.0` (optional, not a peer) | A denoiser for glossy reflections: `denoiser/ffx`. |

```bash
npm install @pmndrs/raytracer @pmndrs/bvh denoiser
```

## Minimal setup

This is [`examples/quickstart`](https://github.com/pmndrs/reflections/tree/main/examples/quickstart) without its
scene and controls. `Reflections.create` builds the G-buffer, the screen-space pass, a baked probe, the denoiser and
the composite in a `RenderPipeline`.

{/* snippet: reflections-create */}
```ts
// A WebGPURenderer with the device limits the passes need, already initialised.
const renderer = await createReflectionsRenderer({ canvas, antialias: false });

const reflections = await Reflections.create(renderer, scene, {
  preset: 'default', // or 'performance'
  rayTracing: false, // true needs @pmndrs/raytracer and @pmndrs/bvh
  denoiser: (device, { roughnessThreshold }) => new FfxReflectionDenoiser(device, { roughnessThreshold: roughnessThreshold ** 2 }),
});

// Where you called renderer.render(scene, camera):
renderer.setAnimationLoop(() => reflections.render(camera));
```

The options are in the [quick start](/getting-started/quick-start#what-reflectionscreate-takes). After the scene or its
environment changes, call `reflections.bake()`. Every piece stays public on the object: `reflections.ssr`,
`.hybrid`, `.probes`, `.trace` and `.pipeline`.

For a cheaper start with no extra passes, bake probes only. See the [quick start](/getting-started/quick-start#probes-only).
To build the frame yourself, see [first frame](/getting-started/first-frame) and the sections below.

## Device limits

The passes ask for more than WebGPU's default limits: up to 64 colour-attachment bytes per sample (the default is 32)
and up to 32 sampled textures per stage (the default is 16). `createReflectionsRenderer` asks for them for you. To
build the renderer yourself, pass `requiredLimits: reflectionsRequiredLimits(adapter)` to `WebGPURenderer`
([Installation](/getting-started/installation#ask-for-the-right-device-limits)).

The ray-traced pass binds 8 storage buffers per stage in three's default setup, which is WebGPU's default limit. It runs
on a plain device. If a configuration needs more, the pass warns once, sets `pass.traceError`, and screen space and
probes continue. See [Troubleshooting](/guides/troubleshooting#ray-tracing-is-off-on-this-device).

A plain `new WebGPURenderer()` works, with one console warning. Its default colour-attachment limit (32 bytes per
sample) cannot hold the G-buffer and the lit image together (36), so the scene is drawn a second time for the lit
image and three's specular weights are estimated. Use `createReflectionsRenderer`, or pass
`requiredLimits: reflectionsRequiredLimits(adapter)`, to avoid the extra draw.

## Known gaps

- Basic, Lambert and Phong materials get no reflections, by design. Use a standard material.
- On three r187, probes need `installCubeArraySupport(renderer)` to use a real cube array. `Reflections.create` does
  it for you. Without it, probes use a 2D array.
- The ray-traced BVH is built once. Moving meshes need `reflections.trace.refit()` each frame. Changed geometry needs a
  new build.
- One `Reflections` per canvas.
- Without a denoiser, glossy reflections are noisy.

## The pieces

`Reflections` is built from these. Use them directly to wire the frame yourself.

| Piece | What it is |
| --- | --- |
| `Reflections` | The one-call setup: all the pieces below, in a `RenderPipeline`. |
| `ScreenSpaceReflectionsPass` | Renders the G-buffer and runs the screen-space tracer (and the ray-traced pass, with `trace`). |
| `HybridReflections` | Resolves the sources, runs the denoiser, and builds the composite. |
| `ReflectionProbes`, `ReflectionProbe`, `reflectionProbes()` | Baked probes and the TSL lookup node for `scene.environmentNode`. |
| `sampleReflectionProbes()` | The same lookup as a function you can call in your own TSL. |
| `FrameGBuffer` | The multi-render-target pass inside the SSR pass. Use it alone to read depth, normals and roughness. |
| `createRaytracerTraceProviderFromObjects()` | Builds the ray-traced provider (`@pmndrs/raytracer`) from three meshes. |
| `applyReflectionsPreset()` | Applies a named bundle of settings at run time. |
| `reflectionsRequiredLimits()` | The device limits to request. |

## The render loop

Each frame, in this order:

```text
ssr.render(scene, camera)   // 1. G-buffer + trace
hybrid.update()             // 2. resolve + denoise
pipeline.render()           // 3. composite into your output
```

`ssr.render` replaces `renderer.render(scene, camera)` for the scene, because it renders the scene into the G-buffer.
The composite node (`hybrid.composite().final`) is the lit image with the reflections in place. Put it in a
`RenderPipeline`, or into your own post-processing chain.

## Resizing

The pass sizes its G-buffer from `gbufferOptions: { width, height }` (default: the renderer's size). When the canvas
changes size, resize the G-buffer and reset the history so the denoiser does not blend frames of different sizes:

```text
ssr.gbuffer.setSize(width, height);
ssr.resetHistory();
hybrid.resetHistory();
```

## Several composites

`hybrid.composite()` can be called again for another place the reflections show, such as a debug view or a second
camera's uv. Build the composites again after you change `reflectionResolution` (`hybrid.rebuild()`, then
`composite()`), because they read different textures at half resolution.

## Camera cuts and jitter

Call `resetHistory()` on a camera cut or a teleport. For an upscaler or TAA, pass the jitter to
`ssr.render(scene, camera, { jitter })`. The showcase's `DisplayAA` helper (`examples/shared/antialias.ts`) shows the
whole wiring with `@pmndrs/upscaler`.
